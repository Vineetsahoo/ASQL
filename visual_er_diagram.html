Component 1

Target Database Relational Schema (Benchmark Domain)

The 8-table enterprise relational schema analyzed by the static analysis AST engine, utilized by engine/rewriter.py for schema-aware SELECT * projection expansion, and seeded in engine/cost_proxy.py for SQLite EXPLAIN QUERY PLAN evaluation. 

erDiagram
    CUSTOMERS ||--o{ ORDERS : places
    ORDERS ||--|{ ORDER_ITEMS : contains
    PRODUCTS ||--o{ ORDER_ITEMS : "included in"
    ORDERS ||--o| INVOICES : generates
    ORDERS ||--o{ SHIPMENTS : fulfills
    DEPARTMENTS ||--o{ EMPLOYEES : employs

    CUSTOMERS {
        INTEGER id PK "Primary Key"
        TEXT name "Customer Name"
        TEXT email UK "Indexed (idx_customers_email)"
        TEXT city "City Location"
        TEXT created_at "Registration Timestamp"
    }

    ORDERS {
        INTEGER id PK "Primary Key"
        INTEGER customer_id FK "References CUSTOMERS(id) (idx_orders_customer)"
        TEXT order_date "Indexed (idx_orders_date)"
        REAL total_amount "Order Total"
        TEXT status "Order Status"
    }

    PRODUCTS {
        INTEGER id PK "Primary Key"
        TEXT name "Product Name"
        REAL price "Unit Price"
        TEXT category "Indexed (idx_products_category)"
        INTEGER stock_qty "Stock Available"
    }

    ORDER_ITEMS {
        INTEGER id PK "Primary Key"
        INTEGER order_id FK "References ORDERS(id) (idx_oi_order)"
        INTEGER product_id FK "References PRODUCTS(id) (idx_oi_product)"
        INTEGER quantity "Quantity Purchased"
        REAL unit_price "Price per Unit"
    }

    INVOICES {
        INTEGER id PK "Primary Key"
        INTEGER order_id FK "References ORDERS(id)"
        TEXT invoice_date "Billing Date"
        REAL amount "Billed Sum"
        INTEGER paid "0: Unpaid, 1: Paid"
    }

    SHIPMENTS {
        INTEGER id PK "Primary Key"
        INTEGER order_id FK "References ORDERS(id)"
        TEXT ship_date "Shipping Date"
        TEXT carrier "Logistics Provider"
        TEXT tracking_no "Tracking Number"
    }

    DEPARTMENTS {
        INTEGER id PK "Primary Key"
        TEXT name UK "Department Unique Name"
        REAL budget "Department Budget"
        TEXT location "Branch Location"
    }

    EMPLOYEES {
        INTEGER id PK "Primary Key"
        TEXT name "Full Name"
        TEXT department FK "References DEPARTMENTS(name) (idx_emp_dept)"
        REAL salary "Annual Compensation"
        TEXT hire_date "Start Date"
    }

Component 2

Static Analysis Engine Meta-Schema (System Pipeline)

The meta-model capturing the operational entities in the static analysis lifecycle: source files, parsed AST query trees, rule evaluation visitors, finding diagnostic records, query rewrites, and SQLite cost proxy plan outputs. 

erDiagram
    SOURCE_DIRECTORY ||--|{ SQL_SOURCE_FILE : scans
    SQL_SOURCE_FILE ||--|{ PARSED_QUERY : parses_into
    PARSED_QUERY ||--o{ FINDING : generates
    DETECTION_RULE ||--o{ FINDING : classifies
    FINDING ||--o| QUERY_REWRITE : enriches_with
    FINDING ||--o| COST_PROXY_EVAL : evaluates_to
    ANALYSIS_RUN ||--|{ FINDING : collects

    SQL_SOURCE_FILE {
        TEXT file_path PK "Unique Path"
        INTEGER size_bytes "File Size"
        BOOLEAN is_empty "Empty Guard"
        BOOLEAN is_malformed "Syntax Guard"
    }

    PARSED_QUERY {
        TEXT statement_id PK "Query UUID"
        TEXT file_path FK "References SQL_SOURCE_FILE"
        INTEGER statement_index "Order in Script"
        TEXT raw_sql "SQL Query Text"
    }

    DETECTION_RULE {
        TEXT rule_id PK "AP-01, AP-02, AP-05"
        TEXT rule_name UK "SELECT_STAR, etc."
        FLOAT base_confidence "Confidence"
    }

    FINDING {
        TEXT finding_id PK "UUIDv4"
        TEXT rule_id FK "References DETECTION_RULE"
        TEXT file_path FK "References SQL_SOURCE_FILE"
        INTEGER line "Source Line"
        INTEGER column "Source Col"
        TEXT snippet "Code Snippet"
        TEXT cost_signal "Cost Proxy Flag"
    }

    QUERY_REWRITE {
        TEXT rewrite_id PK "Rewrite UUID"
        TEXT finding_id FK "References FINDING"
        TEXT rewritten_sql "AST-expanded SQL"
    }

    COST_PROXY_EVAL {
        TEXT eval_id PK "Evaluation UUID"
        TEXT finding_id FK "References FINDING"
        TEXT determined_signal "FULL_SCAN_DETECTED | INDEX_USED"
    }

    ANALYSIS_RUN {
        TEXT run_id PK "Run Timestamp"
        INTEGER total_files "Scanned Count"
        INTEGER total_findings "Findings Count"
    }
Entity Primary Key Foreign Keys Role in Pipeline
SQL_SOURCE_FILE file_path — Encapsulates physical .sql files, isolating syntax/read errors.
PARSED_QUERY statement_id file_path → SQL_SOURCE_FILE Individual AST statements extracted by sqlglot.parse().
DETECTION_RULE rule_id — Declarative AST visitor implementations (AP-01, AP-02, AP-05).
FINDING finding_id rule_id, file_path Core diagnostic artifact adhering to PRD schema specifications.
QUERY_REWRITE rewrite_id finding_id → FINDING Automated column expansion syntheses generated by engine/rewriter.py.
COST_PROXY_EVAL eval_id finding_id → FINDING Physical execution plan diagnostics generated by SQLite EXPLAIN QUERY PLAN.
